# Разработка игры «maze off»

Neon/Tron «побег из тёмного лабиринта», Godot 4.6, GL Compatibility. **Весь мир и UI строятся кодом** — `.tscn`-файлы это заглушки в один узел. Меняешь игру = редактируешь `.gd`, не сцены.

## Запуск Godot (Windows — эта машина)

CLAUDE.md даёт macOS-путь; на этой машине бинарь лежит тут (это ПАПКА с именем `.exe`, внутри консольный exe):

```bash
GODOT="/c/Users/Varenysheva_E_A/Downloads/Godot_v4.6.3-stable_win64.exe/Godot_v4.6.3-stable_win64_console.exe"
```

Всегда проверяй, что команда реально запустилась (вывод не пуст) — bash молча «проходит» на неверном пути.

## Обязательный цикл при любой правке кода

1. Внёс изменения в `.gd`.
2. Добавил ассеты (.mp3/.png)? Сначала: `"$GODOT" --headless --import --path .`
3. Смоук-тест (единственная автопроверка, юнит-тестов нет):

```bash
"$GODOT" --headless --path . res://main.tscn --quit-after 90 2>&1 \
  | grep -iE "error|SCRIPT|parse|invalid|nonexistent" | grep -viE "resources still|audio"
```

Пустой вывод = ок. «1 resources still in use at exit» — безвредно.

4. Смоук гоняет только режим **Уровни**. Трогал код Накала (ember, алтарь, ранги, `enemy_heat`, run-слоты)? Напиши одноразовый harness-скрипт (SceneTree), который вызывает `GameConfig.start_new_run(0)`, потом `change_scene_to_file("res://main.tscn")`, прогоняет кадры и assert'ит по `current_scene`. Удали harness после.
5. Визуал проверяется только скриншот-харнессом: одноразовая сцена, которая инстансит игру, ждёт `RenderingServer.frame_post_draw`, сохраняет `get_viewport().get_texture().get_image().save_png(...)`; запускать ОКОННО (не `--headless`). Удали после.

## Минные поля (реальные баги были здесь)

- **`config.gd`, порядок в `end_run`**: сохранять пока `active_run >= 0`, потом сбрасывать — иначе ран затирает глобальный профиль Уровней. `save_game()` маршрутизирует по `active_run` — не ломай изоляцию профилей.
- **Рендерер не менять**: normal-map-кодирование в `textures.gd` заточено под GL Compatibility; GPU-частицы ненадёжны — только `CPUParticles2D`.
- **Слои CanvasLayer**: мир=0, тьма/тинт=1, HUD=2, screenfx/вспышка=3. `CanvasModulate` темнит только слой мира.
- **Этажи** — вертикальный оффсет `f * _floor_gap` в мировых координатах: мировой Y кодирует этаж.
- **Сетка лабиринта**: `grid[gy][gx]`, проходы на нечётных координатах, стены на чётных; маска открытости стен 8-битная (N=1,E=2,S=4,W=8 + диагонали).
- **Эффект-ноды**: параметры выставлять ДО `add_child`.

## Конвенции

- Комментарии и все игровые строки — **по-русски**.
- Никаких `.tres`: UI — только код-сайд theme overrides, `StyleBoxFlat`, шейдеры.
- **Коммитить только по явному разрешению**, и разрешение одноразовое — новые правки после коммита требуют нового разрешения. `git push` — тем более.
- Новая фича = вписаться в существующий стиль: процедурно, неон, самодостаточные ноды, публичные хуки через методы `main.gd` (`flash_message`, `beep`, `flash_screen`, `reveal` и т.д.).

## Гейм-дизайн: перед фичей спроси себя

- В каком режиме живёт фича — Уровни, Накал, оба? Ветвление через `GameConfig.active_run` (−1 = Уровни, 0..2 = слот Накала).
- Что она делает с экономикой Накала (ember/streak/heat) и с рангами (`_compute_rank`)? Не сломать S-ранг случайно.
- Свет — главный ресурс и главный нерв игры: новая механика должна взаимодействовать с тьмой/светом, а не игнорировать их.
